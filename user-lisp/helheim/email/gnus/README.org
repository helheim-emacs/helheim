* helheim-gnus

#+begin_quote
[!NOTE]
This module configures Gnus as a *Gmail + lieer + notmuch* frontend: Gmail is
the mail store, [[https://github.com/gauteh/lieer][lieer]] keeps a local maildir mirror of it, and [[https://notmuchmail.org/][notmuch]] does all
indexing and search. Gnus itself neither fetches nor stores mail — it is only
the reading and composing interface on top of that stack.
#+end_quote

Gnus configured as a Gmail client, with [[https://github.com/gauteh/lieer][lieer]] mirroring the mailbox and
[[https://notmuchmail.org/][notmuch]] doing all indexing and search. See the [[file:../notmuch/README.org][helheim-notmuch README]] for
setting up notmuch, lieer, and ~msmtp~ — this module assumes that
infrastructure already exists and only configures Gnus on top of it.

** Architecture
*** The pipeline

lieer keeps one flat maildir in sync with Gmail (no folders); notmuch
indexes that maildir and tags messages; ~msmtp~ sends outgoing mail, picking
the account from the =From= header. Gnus itself never fetches mail —
the ~nnmaildir~ backend is configured with =(get-new-mail nil)= — it only reads
what lieer has already delivered. ~helheim-gnus-sync~ (below) is what actually
pulls new mail, by running ~notmuch new~ and letting its hooks drive lieer.

*** Groups are notmuch queries, not folders

Since there are no real folders, every group the user reads is an ~nnselect~
group whose contents are the live result of a notmuch query. These are
declared in ~helheim-gnus-saved-searches~ (name, query, subscription level)
and built by ~helheim-gnus-build-groups~ on ~gnus-started-hook~. Rebuilding is
idempotent: an existing group has its query refreshed in place, so editing
a saved search and restarting Gnus is enough — no manual group
deletion needed.

The one real group (the raw ~nnmaildir~ maildir backing every search) is kept
at level 6, the default ~gnus-activate-level~, so it stays out of the way
without being unreachable.

*** Marks are Gmail state, not local notes

This is the part that surprises: Gnus marks are not private annotations,
they round-trip all the way to Gmail.

| Gnus mark | maildir flag | notmuch tag         | Gmail state |
|-----------+--------------+---------------------+-------------|
| read      | =S=            | ~unread~ (absence of) | read        |
| tick      | =F=            | ~flagged~             | starred     |
| reply     | =R=            | ~replied~             | replied     |

~nnmaildir~ maps marks onto maildir flags, notmuch turns those into tags, and
lieer pushes tag changes back to Gmail. So clearing an article's tick in
Gnus genuinely unstars it in Gmail — it is not a local-only note.

For this to work at all in search-backed groups, ~nnselect~ has to forward marks
to the underlying backend, which it does not do by default: Gnus only forwards
marks when a select method declares =server-marks=, and ~nnselect~ doesn't.
~helheim-gnus.el~ patches the =nnselect= entry in ~gnus-valid-select-methods~
in place (once ~nnselect~ loads) to add =server-marks=, rather than re-declaring
the backend, since ~gnus-declare-backend~ only appends and lookups stop at the
first match.

** Customization

- ~helheim-gnus-account-directory~ :: the lieer-managed maildir directory.

- ~helheim-gnus-notmuch-config~ :: path to the notmuch config, resolved
  the same way notmuch itself resolves it (=$NOTMUCH_CONFIG=, then
  =$XDG_CONFIG_HOME/notmuch/$NOTMUCH_PROFILE/config=, then
  =~/.notmuch-config=).

- ~helheim-gnus-server~ :: The Gnus server the notmuch engine searches against.

- ~helheim-gnus-saved-searches~ :: The list of (name query level) groups.

- ~helheim-gnus-archive-tags~, ~helheim-gnus-trash-tags~, ~helheim-gnus-spam-tags~ ::
  Notmuch tag edits applied by the commands below. ~helheim-gnus-trash-tags~
  and ~helheim-gnus-spam-tags~ must match lieer's own trash/spam tag
  conventions, since lieer's ~remove_local_messages~ means a locally deleted
  file is simply downloaded again on the next pull.

Generated state (cache, saved articles, ~.newsrc.eld~, drafts, outgoing mail)
is redirected under ~user-emacs-directory~ (=var/gnus/=) instead of =$HOME=.

** Usage
*** Sync mail

~helheim-gnus-sync~ runs ~notmuch new~ (whose pre-new hook pulls from Gmail
via lieer and whose post-new hook pushes local tag changes back to Gmail),
then refreshes Gnus. Leave the summary buffer before calling it — Gnus only
writes marks to disk when the summary buffer commits them, not on
every keypress.

*** Summary-buffer commands

These act on the current article in ~gnus-summary-mode~ by editing notmuch
tags directly, rather than using Gnus' own expiry:

- ~helheim-gnus-archive~ — remove from inbox.
- ~helheim-gnus-trash~ — mark for deletion.
- ~helheim-gnus-spam~ — mark as spam.
- ~helheim-gnus-toggle-flagged~ — toggle the ~flagged~ tag, i.e. the Gmail star.

None of these are bound to a key by this module yet.

** Unbound and removed commands

A number of upstream Gnus / evil-collection commands are intentionally left
without a key in this module. Reach any of them with =M-x=, or bind your own.

*** The =g= prefix and motion belong to Hel

Hel owns modal motion and the =g= prefix, so evil-collection's =g=-prefixed
group commands are not bound here. The ones you are most likely to miss:

- =gc= / =gC= :: ~gnus-group-catchup-current~ / ~gnus-group-catchup-current-all~
  — note =c= / =C= are rebound to ~gnus-group-mail~ instead.
- =gu= / =gU= :: ~gnus-group-unsubscribe-current-group~ / ~gnus-group-unsubscribe-group~.
- =gl= :: ~gnus-group-set-current-level~ — still reachable on the upstream =S l=.

*** Removed as irrelevant to a lieer + notmuch mailbox

There is no NNTP server (~gnus-select-method~ is ~nnnil~), ~gnus-agent~ is off,
and mail is exposed as ~nnselect~ notmuch-search groups kept in sync by lieer.
That makes a class of Usenet / agent commands dead weight, and the expiry /
deletion commands actively wrong (they delete maildir files that lieer just
re-downloads), so they are unbound from the group and summary maps (including
the entire =L= list and =B= backend prefixes):

| Command                        | Was | Why removed                                        |
